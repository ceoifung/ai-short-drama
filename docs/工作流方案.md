# AI短剧自动化工作流 · 方案设计

> 目标：把《AI原创短剧教程》的人肉流程（DeepSeek改稿 → 即刻AI出角色 → updream出视频 → 剪映拼接）改造成
> **一个 ZCode 动态工作流（workflow）+ 配套技能（skill）**，AI 负责创作与审核，人只在关键节点拍板。

---

## 一、总体架构：三层分工

```
┌─────────────────────────────────────────────────┐
│ 决策层  workflow 脚本 = "制片人"                    │
│   控制流程、调度 agents、审核门禁(gate)、追问人类       │
├─────────────────────────────────────────────────┤
│ 认知层  创作/审核 agents = "编剧组+审片组"  ← 全自动   │
│   编剧、改写、角色设定、分镜、四级AI审核               │
├─────────────────────────────────────────────────┤
│ 执行层  生成与剪辑 = "片场"                         │
│   A. 平台手动（初期）  B. 浏览器代理（中期）           │
│   C. API 直连生成（终态，全自动化）  + ffmpeg 剪辑     │
└─────────────────────────────────────────────────┘
```

**核心判断**：原教程里人做的活分三类——
1. **纯脑力**（写稿、改稿、分镜、核对）→ 当前 AI 原生可做，**替换掉 DeepSeek**；
2. **感知审核**（看图认角色、看片挑废条）→ 子代理可以直接 Read 图片/视频（本会话已验证），**替换掉人眼**；
3. **平台点击**（即刻AI/updream 网页操作）→ 三条路线渐进（见第五节）。

人类只保留 **2 个检查点**：① 剧本定稿（花钱前）② 成片导出（发布前）。

## 二、流水线设计（7 个 Stage）

### Stage 0 · 素材入库（确定性脚本 + 入口路由，无创作 agent）

**归一化设计**：不管什么形态的素材，都归一成同一份产物——`00_source/raw.txt`（源文本）+
`source_meta.json`（来源类型/原始文件/字数/分集数等元数据）。下游 Stage 1~6 完全不感知输入形态，
只有 Stage 1 的**第一个 agent 按来源类型切换**（可插拔入口）。

| 输入形态 | 归一化方式（确定性脚本） | Stage 1 入口分支 |
|---|---|---|
| 视频/音频文件 | 本地 faster-whisper 转写（复用 `E:\ai-subtitle`）→ 台词稿 | **小说化编剧**（提示词1）→ 改写师 |
| 小说/故事文本 | 清洗排版 + 字数统计，原文直存 | **分集策略师**（选段/分集）→ 剧本化改编 → 改写师 |
| 一句话创意/题材 | 原文直存 | **原创编剧**（扩写成完整故事）→ 改写师 |
| 已有剧本/分镜脚本 | 结构识别（有无镜头标记） | 轻润色 → 直接进改写（或按参数跳过改写） |
| 抖音/网页链接 | P2 浏览器抓取；P1 提示改为手动下载视频 | 同视频 |

- **类型识别**：按扩展名 + 字数启发式自动判断（`.mp4/.wav`→媒体；`>2000字`→小说；`<200字`→创意），
  也支持 `source_type` 参数强制指定，识别不了就追问。
- **小说文本的特殊处理**：小说自带叙事，跳过"小说化"步骤；但小说动辄几千上万字，先由
  **分集策略师** agent 输出分集大纲（每集一个冲突点+结尾钩子，天然支持一源多集），
  再逐集走"剧本化改编 → 爆款改写"。改写用变体提示词（`p2_rewrite_novel.txt`），
  改写对象从"镜头脚本"换成"小说段落"。

### Stage 1 · 编剧流水线（3 agent + 1 审核，带循环）
| 步骤 | Agent | 干什么 |
|---|---|---|
| 1.1 | **小说化编剧** | 用提示词1（逐帧分析模板）+ 转写稿 → 小说化正文 + 逐镜头【场景】【景别/机位】 |
| 1.2 | **爆款改写师** | 用提示词2（先自确认规则再改写）→ 黄金三秒开场 + 冲突升级 + 互动钩子结尾 |
| 1.3 | **剧本审核官** | 按 rubric 打分出 verdict JSON（见第四节 L1），不合格 → 携问题清单打回 1.2 重改，最多 2 轮，仍不过 → 追问人类 |

⏸ **检查点①（人工）**：workflow 中途弹问题——"剧本已生成于 01_script/，回复'继续'或直接给修改意见"。

### Stage 2 · 资产设定（并行 2 agent + 1 审核）
- **角色设定师**：剧本 → `characters.json`（每人：名字/年龄/外貌/服装/声线/参考图文件名规范）。
- **场景道具师**：剧本 → `scenes.json` + `props.json`。
- **资产审核官**：核对剧本里出现的角色/场景/道具是否全部登记、命名无冲突、描述可直接用于出图。
- 产物同时生成一份**给即刻AI的粘贴包**（项目参数清单：9:16 / 真人现代短剧 / Seedance 2.0 Mini）。

### Stage 3 · 分镜设计（1 agent + 1 审核 + 时长门禁）
- **总分镜师**：剧本 + 资产表 → `storyboard.json`：N 个镜头卡片，每张含
  `{id, 时长(5s), 【画面】【动作】【镜头】【台词】, 出场角色[], 场景, 道具[], 生成提示词(≤1000字)}`。
- **分镜审核官**（见第四节 L3）：时长总和 = 单集目标（15s×镜头数）、提示词四要素齐全、
  引用的角色/场景必须在资产表里存在（防"连戏崩"）、前后镜头场景/人物衔接合理。
- 门禁失败 → 打回总分镜师修订对应镜头。

### Stage 4 · 生产包（确定性脚本，无 agent）
把 storyboard.json 渲染成 **"傻瓜式执行手册"** `04_production/`：
- `updream_node_01.md … node_N.md`：每个节点的完整提示词（直接整段复制）+ 需勾选的参考图清单（角色A+场景B+道具C）+ 参数（Mini/480P/9:16/开音频/15s）。
- `manifest.json`：全部镜头的机读版（供浏览器代理或 API 通道消费）。
- `checklist.md`：即刻AI/updream 的点击步骤清单（照教程第七节的顺序）。

### Stage 5 · 视频生成（三通道，按阶段选择）
| 通道 | 方式 | 自动化程度 | 建议 |
|---|---|---|---|
| A 手动 | 人按生产包在平台点击 | 生成 0% 自动，但包已把思考全做完 | **P1 先上** |
| B 浏览器代理 | browser-use agent 驱动 updream：建节点→贴词→挂参考图→点生成→轮询进度→批量下载 | ~90%（登录/验证码偶尔需人） | P2，节点操作高度重复最适合 |
| C API 直连 | 智谱 CogVideoX / 即梦开放平台 等文生视频+图生视频 API | 100% | P3 终态，你已在 GLM 生态，CogVideo 是天然候选 |

### Stage 6 · 质检 + 自动剪辑
- **片场质检员**（fan-out 并行，每条片段一个）：
  - 视觉：Read 视频片段 → 对照分镜卡打分（画面相符度、角色服装跨镜头一致性）；
  - 听觉：whisper 转写片段 → 台词是否在、**长静音段时间戳**（教程里人肉"剪掉不说话的段"就是它）。
  - 产物：`06_review/qa_shot_NN.json`，不合格片段列入重生成清单。
- **剪辑师（确定性 ffmpeg 脚本）**：按质检的静音时间戳裁剪 → 拼接 → 缩放 9:16 铺满 → `07_final/第X集.mp4`。
  教程用剪映做的事（剪静音/调比例/拼接/导出）ffmpeg 全部可自动完成。

⏸ **检查点②（人工）**：成片路径推给你，确认后可发布。

## 三、Agents 协同调度（workflow 编排要点）

**编排器**：一个动态 workflow 脚本当"制片人"，本身不创作，只做四件事：

1. **顺序门禁（gate）**：Stage 1→2→3 串行，每个 stage 末尾跑审核 agent，`verdict.pass == true` 才放行；
   失败则把 `verdict.issues` 拼进 worker 的下一轮提示词里重试（**带反馈的重试**，不是盲重跑），上限 2 轮，仍失败用 workflow 的追问机制（dwfq）升级给人类。

2. **并行扇出（fan-out）**：
   - Stage 2 的角色/场景两个 agent 并行；
   - Stage 6 的 N 条片段质检并行（`max_concurrency` 控制，避免 token 爆）。

3. **磁盘即接口**：所有 stage 产物落盘到项目目录（见下方结构），agent 之间不靠内存传话——
   好处：断点可续（AmendWorkflow/Resume 复用已完成 stage）、人随时能打开看半成品、审核 agent 复读方便。

4. **检查点追问**：workflow 中途向人类发问题（剧本定稿、生成通道选择、成片确认），不阻塞其他并行任务。

**Agent 名册**（8 个认知 agent + 1 个可选浏览器 agent）：

| Agent | 类型 | 输入 | 输出 |
|---|---|---|---|
| 小说化编剧 | 文本 | 转写稿+提示词1 | novel.md |
| 分集策略师 | 文本 | 小说原文+目标集数 | 分集大纲（每集冲突点+钩子） |
| 原创编剧 | 文本 | 一句话创意 | 完整故事初稿 |
| 爆款改写师 | 文本 | novel/初稿+提示词2 | rewritten.md |
| 剧本审核官 | 文本 | rewritten.md | verdict.json |
| 角色设定师 | 文本 | rewritten.md | characters.json |
| 场景道具师 | 文本 | rewritten.md | scenes/props.json |
| 总分镜师 | 文本 | 剧本+资产表 | storyboard.json |
| 分镜审核官 | 文本 | storyboard+资产表 | verdict.json |
| 片场质检员×N | **视觉+听觉** | 片段mp4+分镜卡 | qa_shot_NN.json |
| 平台操作员(P2) | 浏览器 | manifest.json | 平台上的生成任务 |

提示词1/2 从 `提示词.doc` 抽出，做成 skill 目录下**可编辑的配置文件**（`prompts/p1_novelize.txt`、`prompts/p2_rewrite.txt`），你随时调优，不动代码。

## 四、AI 审核设计（你问的核心：怎么交给 AI 审核）

四级 rubric，每级都是"审稿人 agent 拿着清单打分 → 结构化 JSON 结论"：

**L1 剧本审核**（文本）
- 合规：无暴力特写描写、无脏话、无违禁题材（抖音创作者中心规则）
- 爆款要素：黄金三秒冲突✓ 冲突升级节奏✓ 结尾互动钩子✓
- 质量：角色名前后一致、台词口语化不像 AI、逻辑贴近现实
- 输出：`{pass, score, issues:[{severity, location, suggestion}]}`

**L2 资产审核**（文本，为出图服务）
- 剧本中每个出场对象都已登记；外貌描述可直接生成三视图；参考图命名规范

**L3 分镜审核**（文本，最关键的一道）
- 总时长 = 目标时长；每张提示词 ≤1000 字且四要素齐全
- **引用完整性**：镜头里出现的角色/场景/道具必须存在于资产表（否则生成时挂错参考图→人物崩）
- **连戏**：相邻镜头场景转换合理、出场人物与剧情对应

**L4 成片审核**（视觉+听觉，替换人眼审片）
- 画面与分镜卡相符度（景别、动作、出场人物）
- **跨镜头人物一致性**：抽查多片段对比同一角色服装长相
- 音频：台词存在；静音 >3s 的区间时间戳（直接喂给 ffmpeg 自动裁）
- 不合格片段自动列入重生成清单，附上"哪里不对"的描述供下轮提示词修正

## 五、项目产物目录结构

```
E:\AI短剧\projects\<剧名>\          ← 每部剧一个目录，即 workflow 的"数据库"
  00_source\      source_meta.json（来源类型等元数据）+ raw.txt（转写稿/小说原文/创意）
  01_script\      novel.md / rewritten.md / review_*.json / 分集大纲.md
  02_assets\      characters.json / scenes.json / props.json（+图片）
  03_storyboard\  storyboard.json / shot_NN.md
  04_production\  updream_node_NN.md / manifest.json / checklist.md
  05_footage\     平台下载的原始片段（重命名 1,2,3…）
  06_review\      qa_shot_NN.json / 重生成清单.md
  07_final\       第X集.mp4
```

## 六、落地路线（建议三期）

| 期 | 内容 | 价值 |
|---|---|---|
| **P1 本地全自动版** | Stage 0-4 + 6：转写→编剧→审核→分镜→生产包→（人下载素材后）质检+ffmpeg 剪辑。生成仍手动 | 一次跑通，替换 DeepSeek 和人肉分镜，约省 60% 工时 |
| **P2 浏览器代理** | 加"平台操作员"agent：updream 建节点/贴词/挂图/生成/下载全自动；即刻AI 建项目出角色图 | 再省 30%（平台点击是最重复的部分） |
| **P3 API 直连** | 生成通道换成 CogVideoX / 即梦 API，manifest 直接驱动 | 全链路无人值守，可批量铺量 |

P1 的交付物：**1 个保存的动态 workflow**（`ai-short-drama`，带参数：剧名/素材路径（视频·音频·小说·创意任一形态）/来源类型（auto 自动识别）/单集时长/风格/集数）+ **1 个技能**（收纳 whisper/ffmpeg 脚本与提示词配置、文档化调用方式）+ 上面的项目目录约定。

## 七、需要你拍板的决策

1. **生成通道**先走哪条？（建议：P1 先手动+生产包，同周期我可以把 P2 的 updream 浏览器代理做出来试稳定性）
2. **单集规格**默认值：15 秒/集、Seedance 2.0 Mini、480P、9:16、真人现代短剧风——照教程默认，还是你有别的偏好？
3. **对标素材**来源：本地视频文件为主（whisper 转写），还是需要我加"抖音链接→自动抓取"的浏览器步骤？（建议先本地，抓取放 P2）
